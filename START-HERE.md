# Start here

Use this manager when testing a website, web application, shared component or complete user journey against WCAG 2.2 Level AA.

## Before testing

1. Agree which website, languages and release are in scope.
2. Select representative pages, shared components and complete user journeys.
3. Record the browsers, devices, viewport sizes and assistive technologies available.
4. Use safe test data. Never put real user information, credentials or unnecessary personal data in evidence.
5. Run the automated pre-check, then complete every applicable manual test.

## During testing

- Use the sidebar to move between preparation guidance, the test catalogue, guided test run, component procedures and WCAG groups.
- Use search, test-type filters and theme chips to find the procedures relevant to the page, component or journey.
- Complete **Set up this test run**, then add applicable procedures to **My test plan**. The sidebar shows selection and WCAG-criterion coverage; the plan and results are saved in the current browser.
- Use **Start testing** to move through the selected tests in sequence. Record execution status, criterion outcomes, the actual result, evidence reference, issue ID and any limitation.
- Use **Export CSV** to save or share the complete run, and **Import CSV** to restore it in another browser. Treat the exported file as test evidence and store it according to the project's data-handling rules.
- Use **Open test** in a catalogue row, or open a selected test from the sidebar plan. Use the numbered step tabs to work through one action card at a time; Left Arrow, Right Arrow, Home and End move between tabs.
- In each step card, complete the **Action**, confirm the **Expected result**, and save the item named under **Record** or **Evidence to save** before moving to the next step.
- Record the items listed under **What to record**, including the exact control, state, key sequence and observed result.
- Use each procedure's success-criterion links, open the relevant WCAG group, run the criterion-level manual check, then decide and record the relevant WCAG outcome.
- Complete the remaining WCAG test groups so that every applicable criterion is tested, including requirements that do not belong to one component.
- Check default, opened, loading, empty, error and success states where they exist.
- Record what actually happened, not what the implementation appears intended to do.
- Follow the Action, Expected result and Record fields for every applicable criterion-level check.
- Record a separate outcome for every success criterion listed in a grouped test.
- Keep the mouse or trackpad unused during keyboard-only tests.
- Save enough evidence for another tester to identify the target and reproduce the result.

## Result choices

- **Pass:** Every applicable target and state tested for that success criterion met the stated requirement.
- **Fail:** At least one applicable target failed the requirement. Record the exact target and state.
- **Not applicable:** The completed inventory shows that the website sample contains no content or function to which the criterion applies.
- **Needs specialist review:** This is an execution status, not a criterion outcome. Use it when the criterion applies but the available evidence or tester expertise cannot support a reliable decision.
- **Not tested:** This describes incomplete execution, not a criterion outcome.

The only completed criterion outcomes used by this manager are pass, fail and not applicable. Keep the outcome empty while execution is not started, in progress, blocked or awaiting specialist review.

## When to stop and escalate

Ask an accessibility specialist when:

- accessible names, roles, relationships or live announcements cannot be verified reliably;
- an exception described by WCAG may apply;
- colour sampling, flash analysis or accessibility-support behaviour is uncertain;
- an external platform prevents completion of the user journey;
- different browsers or assistive technologies produce conflicting evidence;
- a pass would depend only on an automated tool result.

Continue with unaffected tests while the question is reviewed.
